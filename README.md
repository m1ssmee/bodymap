# BodyMap — your body, explained

**Live demo:** https://bodymap-qu9s.vercel.app

Upload a prescription, blood report, X-ray, MRI, CT or ultrasound. Gemini reads it, every finding is pinned to a 3D body, and everything is explained in plain language for older patients. Records stay in the browser (localStorage). No login, no database.

## Run locally
```bash
cp .env.example .env.local   # put your Gemini keys in GEMINI_KEYS
npm install
npm run dev
```

## NLP: Ask about your records
`/ask` answers questions in the patient's own words, typed or spoken, in English or Hindi, using only their records (retrieval-augmented generation, RAG).

1. **Passages** (`lib/retrieve.ts`): each record is split into one short passage per fact: a finding, a lab value, a medicine, a piece of advice, a lab's trend over time, the current medicine list, upcoming check-ups.
2. **Preprocessing**: Unicode normalisation, lowercasing, tokenising letters and digits (Devanagari vowel signs included), dropping the nukta dot (ज़ = ज), removing English and Hindi stop words, and light Porter-style stemming of English words (kidneys → kidney).
3. **Query expansion**: a small English/Hindi medical synonym map turns everyday words into the words records use (शुगर / sugar → HbA1c, glucose, metformin). Expanded terms weigh 0.6, typed words 1.
4. **Ranking**: BM25 (k1 = 1.5, b = 0.75) over the passages, in the browser. With no word in common, the patient summary, current medicines and latest records are used instead.
5. **Answer** (`app/api/ask/route.ts`): the top 8 passages go to Gemini, which may answer only from them and returns the ids it used. These show as source links under the answer.

Voice input uses the browser's speech recogniser (`en-IN` / `hi-IN`; Chrome, Edge, Safari). Each answer has a "How this answer was found" panel listing the searched words (expanded ones marked) and every passage's BM25 score.

## Deploying
Vercel is connected to this GitHub repo. Every push to `main` redeploys https://bodymap-qu9s.vercel.app automatically. Pushes to other branches get their own preview link.

Set `GEMINI_KEYS` (and optionally `GEMINI_MODEL`) under the Vercel project's Settings > Environment Variables, then redeploy once.

## Gemini notes
- These keys only work on the Gemini **Interactions** API (`/v1beta/interactions`), which the route uses.
- Models tried in order: gemini-3.6-flash, gemini-3.5-flash, gemini-3-flash-preview. 3.7/3.8 Flash were overloaded on 28 Oct 2026. Override with `GEMINI_MODEL`.
- Each request rotates keys; any key that fails (quota, billing, invalid) is skipped. Lab severity is computed from the printed reference range, not guessed by the model.

## 3D body
`public/body.json` is generated by `node scripts/build-body.mjs` from the MakeHuman base mesh, skeleton and skin weights (CC0, downloaded once into `scripts/.cache`). Re-run it only to change the pose or the organ shapes.

## Demo packet
- `public/demo/` — images the app uses (preloaded record thumbnails + the two "Try a sample" uploads).
- `demo-docs/print/` — PDFs to print for the live demo.
- `demo-docs/make.py` — regenerates both. Patient, doctors and labs are fictional.

## Android app
`mobile/` is a Capacitor 8 app (`app.bodymap`) that opens the live site (https://bodymap-qu9s.vercel.app) in a WebView. It has its own `package.json`, and Vercel never installs or builds it. The app adds `BodyMapApp` to its user agent, which turns on the calm app mode. The site reaches the native plugins through `window.Capacitor.Plugins` (see `lib/native.ts`); on the website they are simply absent.

What the app adds over the website:
- **Reminders**: a notification at 8 AM, 2 PM and 8 PM listing that time's medicines, and one at 9 AM when a check-up from Upcoming is due, for every family member. Turned on from the Medicines page (`components/AppNative.tsx`, `lib/reminders.ts`). Android 14+ needs "Alarms & reminders" switched on for exact times; the card offers it, otherwise reminders may come a few minutes late.
- **Scan a document**: "Take a photo" opens Google's ML Kit document scanner (finds the edges, crops; several pages become one PDF). The first time, Google Play downloads the scanner and the camera opens instead.
- **Share**: a record's summary as text, through Android's share sheet (WhatsApp, SMS…).
- **Read aloud** with the phone's own voice (Hindi works on phones with Google's speech services), and the **back button** goes back a page, then leaves the app from the first page.

Build (needs Java 21 and the Android SDK; Android Studio bundles both, or `brew install openjdk@21 android-commandlinetools`):
```bash
cd mobile && npm install && npx cap sync android && cd android && ./gradlew assembleDebug
```
The APK is `mobile/android/app/build/outputs/apk/debug/app-debug.apk`. Install it with `adb install -r` or open the folder in Android Studio.

Test against a local server:
- Emulator: `CAP_SERVER_URL=http://10.0.2.2:3000 npx cap sync android`, then rebuild.
- Phone on the same Wi-Fi: start the server with `npm run dev -- -H 0.0.0.0`, then `CAP_SERVER_URL=http://<Mac LAN IP>:3000 npx cap sync android`.
- The dev server's live reload can bounce the app to its offline screen after the scanner or another app was open; test that kind of flow against `npm run build && npx next start -p 3001` instead.
- When you're done, run plain `npx cap sync android` again. Otherwise the app keeps loading your local server.

The app shows whatever is deployed on Vercel, so web changes reach it only after a push to `main`. Native changes (plugins, icons, `mobile/`) need a new APK.

Offline: if the site can't load, the app shows `mobile/www/offline.html` in English and Hindi with a big "Try again" button. Capacitor serves that page from the app itself, so after every sync `mobile/set-server-url.mjs` writes the site's address into the copied page.

Icons and splash come from `mobile/assets/`; the reminder icon is `res/drawable/ic_stat_bodymap.xml`. Regenerate the app icons with `npx capacitor-assets generate --android --iconBackgroundColor '#5b7f73' --splashBackgroundColor '#f6f4ef' --splashBackgroundColorDark '#f6f4ef'`.
